## 硬件和模型

- Intel Core i7-14650HX，8P+8E，24 个逻辑处理器；32 GB DDR5-5600。
- NVIDIA RTX 4060 Laptop，8 GB VRAM，sm_89；PCIe 4.0 x8。
- Windows。MSVC 14.44.35207，CUDA 13.0.48；CUDA 架构目标 89，Release，portable CRT。
- 模型文件名：`Qwen3.8-Flash-Next-Gyro-S-abliterated-TQ1_0.gguf`。GGUF 为 58,487,015,904 字节，SHA256 为 `783e1af72859c48146162840f1a2173922c03e4befaeea4add7578ad25c303a3`。
- 专家包实际类型 GU=TQK6 (145)、down=TQK7 (146)，H=2560、FF=640，48 层 × 512 专家。文件名中的 TQ1_0 不代替实际专家类型说明。
- 专家包约 25.5 GiB，GGUF 约 54.5 GiB；使用混合 CPU/GPU 执行与文件映射，模型不是完全装入 8 GB 显存。
- `STRATA_ROUTE_TAIL_SKIP=0`，`STRATA_ROUTE_PRIOR=0`，8192 上下文容量，FP16 KV，单并发，MTP 开启。

## 测量定义

生成 TPS 取本机服务 `/metrics` 中 `decode_tok_s`；首字延迟为客户端发出请求至首个文本/思考/工具片段；含首字等待的整体速度为总输出 token 除以请求总耗时。模型加载不计入，但请求内的数据读取和补页计入。测试输出达到指定 token 数才算完整正式请求。

每个会话重启，先预热一条公共图书馆说明，再测中文自行车维护、Python TTL/LRU 缓存模块、100 项家庭整理 JSON。完整提示与生成文本保存在每次结果的 `messages` / `content` 字段。温度 0、seed 42、关闭思考；即使如此，动态专家缓存、浮点舍入和推测路径也可能使文本不同。

主正式轮顺序为：r2 → r2-tuned16 → r3-plain16 → r3-chain16 → r3-pgo-chain16 → r3-pgo-chain16 → r3-chain16 → r3-plain16 → r2-tuned16 → r2。每组 256 token 预热，三项各 256 token；每个候选 6 次正式输出。

追加轮为：r3-plain16 → r3-base16（PGO）→ r3-base16 → r3-plain16。追加轮没有延长 lookup chain。普通 r3 两轮合并有 12 次正式输出，其余各 6 次。合并数据中的 `index` 是重新编号；原始会话编号见各轮文件。

筛选轮有 128 和 256 token 两种长度，不应混成同一正式对照。`data/r3/experiments/20261030-134656` 在 spec=0 时失败，但此前成功的会话保留。性能是描述性结果，没有置信区间或显著性证明，不能据此认定 24.15 与 24.10 有稳定差距。

## 计算路径和失败结果

r1 为 MSVC 的 trellis 整数解码展开及混合核心任务分配；r2 加入有界 64 位状态读取、固定 1–8 token 模板和 AVX-VNNI 整数点积。保留浮点缩放、FMA 与归约顺序，运行时检查 ISA，支持关闭本地 r2 路径。完整补丁在同一上游基线上独立应用，不能叠加 r1 完整补丁与 r2 完整补丁。

实验 r3 增加 AVX2 激活展开、批内只读激活复用、并行 Hadamard/量化；PGO 只对部分 CPU 热点翻译单元启用。这些实验没有进入最后部署。

- 普通 r3：720 批逐位对照；PGO：1008 批，包含输入重用、超容量回退、任务数、线程数和 token 数变化。浮点槽位计数包含未使用槽位，不能当作独立模型评测题数。
- 硬件半精度转换和更大循环展开通过 5120 次内核检查，但没有足够收益，未合入完整补丁。
- spec=0 无法加载该原生专家包；随后保留 `--spec 2` 并移除 MTP，单独测不使用 MTP 的路径。
- 部分驻留加直接读盘显著倒退；缓存模式有所恢复，受 Windows 提交内存限制。申请 16 GiB 实际被自动压至约 9 GiB。
- 精确 PGO 共享计数器开销过大，32 token 训练请求没有完成。有意用 pgosweep 保存已捕获计数器后终止训练进程，恢复 r2；训练速度不纳入成绩。见 [采样记录](../data/r3/pgo-training.json)。
- 早期筛选中出现过更高的 128 token 成绩；正式选择不使用这些峰值替代 256 token 的对照。

## 复现状态

通过：本机 CUDA 构建、CPU 数值一致性检查、正式性能对照、模型文件完整哈希、清理后服务重启和 ECPA 实际生成。

未运行：模型能力评分、长上下文性能、其他硬件和操作系统、HIP/SYCL 构建、修改后默认构建的完整二进制一致性比较。此次发布整理没有重新下载工具链或重跑模型性能；新提供的复现辅助脚本只进行了离线检查。

`archive/harness/` 保存原测试程序，私有路径替换为 `${STRATA_ROOT}` / `${WORKSPACE}`；它们是记录，未经替换不能直接执行。原程序包含更早的能力测试工具，但本仓库 r2/r3 性能数据只调用其流式请求和监控部分，不把未运行项目算作验证。

`data/export-manifest.json` 给出导出前后文件哈希。JSON 的认证字段已移除，本地路径作占位处理；数值、提示、生成文本、失败和顺序保留。完整源码补丁保持原始字节与哈希；发布检查发现 r2-only 差量补丁的 CRLF 换行会导致 Git 应用失败，因此该文件仅统一为 LF，原版保存在 `archive/patches/`。实验 PGO 补丁中的 `E:/Strata/...` 是当时的固定构建路径，需要使用者自行调整。历史 BUILD.json 中的本机状态不是新下载电脑已通过验证的声明。
